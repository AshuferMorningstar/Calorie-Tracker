# Calorie Wise Overview

Calorie Wise is a calorie tracking and meal logging app built for fast daily use. It helps users search foods, add meals, track calories and protein, plan meals, and keep their progress synced across sessions.

## What the app does

- Log meals and snacks with calories, protein, amount, and unit handling.
- Search a built-in food database with Indian foods, fruits, vegetables, and common dishes.
- Track daily totals and browse past days with the calendar and history views.
- Support onboarding so users can set up goals and profile details.
- Sync user data with Firebase and local storage for offline-friendly behavior.
- Allow guest sign-in through anonymous authentication.

## Stack

- React 18 for the UI.
- Vite for development and production builds.
- React Router for page navigation.
- Firebase Auth and Firestore for sign-in and cloud sync.
- Dexie for local data handling where needed.
- Plain CSS for styling and page layout.

## Project structure

- `src/App.jsx` is the top-level app shell and route layout.
- `src/main.jsx` mounts the React app into the DOM.
- `src/pages/` contains the main screens like onboarding, tracking, calendar, and profile.
- `src/components/` contains reusable UI pieces such as cards, splash screens, and small layout helpers.
- `src/context/` holds shared state and sync-related context.
- `src/hooks/` contains reusable React hooks.
- `src/services/` contains Firebase and auth helpers for sign-in and sync.
- `src/data/` contains the food datasets used by the tracker.
- `public/assets/` stores app images, logos, and manifest icons.
- `index.html` provides the Vite entry HTML and icon links.
- `dist/` is the production output generated by the build.

The app is organized so that page logic stays inside `src/pages/`, shared UI stays in `src/components/`, and backend or sync concerns stay in `src/services/` and `src/context/`.

## Scripts

- `npm run dev` starts the local Vite dev server for development.
- `npm run build` creates the production bundle in `dist/`.
- `npm run preview` serves the built app locally so you can test production output.

These scripts are the only ones defined in `package.json`, so the workflow is intentionally simple: develop locally, build for release, and preview the final bundle before deploying.

## Notes

- The app uses React 18 with Vite, so the codebase follows a modern component-based structure with fast refresh in development.
- Firebase handles authentication and cloud sync, while local storage keeps the app usable offline or when sync is delayed.
- The food tracker uses built-in datasets for common foods, fruits, vegetables, and Indian meals so users can log quickly without manual nutrition entry.
- The app uses both a vector logo for in-app UI and a PNG logo for icons and manifest files.
- A production build should be regenerated after asset changes so `dist/` stays current.
- If you change logos or app icons, refresh the browser hard to avoid cached favicon or manifest files.
